# StudyCoach 개발 순서

결정일: 2026-09-04  
기준 버전: `0.1.20` 실기 합격

## 최종 방향

StudyCoach는 **필기 앱이 본체이고 PDF와 AI가 그 위에 붙는 구조**로
개발한다. Goodnotes와 Notability의 공개 기능과 사용 흐름을 적극적으로
참조하지만, 비공개 내부 구조를 추측하거나 화면·자산을 그대로 복제하지
않는다.

현재 사용자가 만족한 PaperKit 필기 엔진과 `0.1.19` PDF 렌더러는
보존한다. 한 시험 버전에서는 한 가지 큰 축만 바꾸며, iPadOS 26 실기
시험을 통과하기 전에는 다음 축을 합치지 않는다.

다른 큰 축을 한 버전에 합치지는 않는다.

## 지금 바로 이어갈 세 단계

### 1단계 — `0.1.20`: 필기 엔진과 자체 UI 사이의 연결 검증 — 완료

이 버전은 예쁜 최종 툴바를 만드는 버전이 아니다. 자체 UI가 PaperKit
필기감을 전혀 바꾸지 않는다는 사실을 확인하는 안전 시험이다.

변경 범위:

- `PaperMarkupViewController`, `PaperMarkup`, PDF 배경, 타일 캐시,
  확대·이동 구조와 논리 페이지 크기는 변경하지 않는다.
- `PKToolPicker`는 활성 상태로 남겨 Pencil 두 번 탭과 시스템 도구
  연결을 유지하되, 화면 팔레트는 숨길 수 있게 한다.
- StudyCoach 최소 툴바에는 펜, 형광펜, 지우개, undo, redo만 둔다.
- **Apple 도구 / StudyCoach 도구** 전환을 시험용으로 제공한다.
- 앱 UI에서 바꾼 도구를 시스템에 전달하고, 두 번 탭 등으로 시스템이
  바꾼 도구를 앱 UI에 다시 반영한다.

코드 시험:

- 앱 도구 식별자와 시스템 도구 항목의 매핑
- 앱→시스템→앱 갱신이 무한 반복되지 않음
- 알 수 없는 미래 시스템 도구가 들어와도 충돌하지 않음
- 편집 컨트롤러 교체·페이지 이동 후 현재 도구가 다시 적용됨

iPadOS 26 합격 시험:

1. Apple 기본 UI와 자체 UI에서 같은 펜으로 같은 글씨를 쓴다.
2. 지연, 필압, 보정, 선명도, 좌표가 달라지지 않아야 한다.
3. 펜·형광펜·지우개·undo·redo가 모두 작동해야 한다.
4. Pencil 두 번 탭으로 펜↔지우개가 바뀌고 자체 UI 표시도 따라가야 한다.
5. 손가락 이동과 두 손가락 확대가 그대로 작동해야 한다.
6. 실패하더라도 Apple 도구 UI로 돌아가 즉시 필기할 수 있어야 한다.

하나라도 실패하면 전체 UI를 덧붙이지 않고 연결층만 수정한다.

### 2단계 — `0.1.21`: 실제로 사용할 필기 툴바 완성

`0.1.20`의 1~13 실기 시험이 모두 통과했다. 다음 구현은 Apple 도구창을
그대로 흉내 내지 않고 StudyCoach 상태가 정밀 값을 직접 소유한다.

- Goodnotes·Notability처럼 자주 쓰는 도구와 선택 도구의 맥락 패널
- 펜·형광펜별 10단계 굵기와 연속 미세 조절
- 도구별 빠른 색상 슬롯과 프리셋
- `PKInkingTool.validWidthRange` 안에서 더 얇은 최소 굵기
- 형광펜 기본 azimuth 프리셋과 상세 조절
- 정밀/부분/획 전체 지우개와 각 지우개의 폭
- 지우개 뒤 이전 펜으로 자동 복귀 옵션
- 자유형 올가미
- 도구 순서 변경·숨김과 툴바 위치 저장
- `UIPencilInteraction`을 통한 두 번 탭과 지원 기기의 Pencil Pro 스퀴즈
  직접 처리

텍스트와 이미지는 PaperKit의 `insertNewTextbox`/`insertNewImage`로
구조화 요소를 삽입하는 다음 하위 묶음이다. 점선·파선 자유 필기는 공개
`PKInkingTool`에 직접 대응하는 pattern 속성이 없어 별도 격리 시험을
거친다. 녹음은 버튼 자리를 툴바에 예약하되 실제 파일/Note Replay 기능은
문서 저장 구조가 안정된 뒤 `0.5.x`에서 구현한다. 상세 경계는
`docs/TOOLBAR_ARCHITECTURE.md`를 따른다.

iPad 합격 기준은 기능 존재뿐 아니라 **기존 PaperKit 필기감이 완전히
같은가**이다. 이 버전에서도 앱이 Pencil 획을 직접 만들지 않는다.

### 2B단계 — `0.1.23`: 툴바 밀도와 필기 설정 보정

- 문서 조작 줄과 도구/스타일 줄을 각각 얇은 캡슐로 유지한다.
- 도구는 그림으로 표시하고 한글 이름은 접근성 레이블로만 남긴다.
- 굵기, 색상, 투명도, 각도, 지우개 모드는 한 줄에서 가로로 스크롤한다.
- 형광펜 투명도는 10–80% 범위로 직접 조절한다.
- 펜과 형광펜의 열 단계가 native 유효 범위에서 확실히 구분되게 한다.
- PaperKit 필기 엔진, 렌더러, PDF 기하와 저장 형식은 바꾸지 않는다.

### 2C단계 — `0.1.24`: 문서 탭과 도구 설정줄 보정

- 열린 PDF의 식별자와 이름만 상단 탭으로 보관하고, 선택된
  `PDFDocument` 하나만 메모리에 올린다.
- 도구 아이콘을 가운데 첫 줄에 두고, 선택 도구를 다시 누르면 그
  도구의 설정줄을 열거나 닫는다.
- 펜·형광펜은 빠른 색상 다음에 충분히 긴 폭 슬라이더와 실제 폭 숫자를
  둔다. 지우개는 폭 다음에 전체/부분/정밀 모드를 둔다.
- marker는 선택된 `azimuth`로 처음부터 생성하고, vector 지우개는 선택한
  폭이 0으로 축소되지 않게 전달한다.
- PaperKit 필기 처리, PDF 기하, 렌더러와 PaperMarkup 형식은 바꾸지 않는다.

### 2D단계 — `0.1.25`: 플로팅 팔레트와 고급 도구 보정

- 전체 도구 영역을 PDF와 독립된 `ZStack` 오버레이로 배치해 설정줄을
  열고 닫아도 PDF의 위치와 fit이 바뀌지 않게 한다.
- 주 도구줄과 설정줄은 비슷한 고정 폭 안에서 각각 스크롤되고, 짧은
  내용은 가운데 정렬한다.
- 실선은 기존 native PaperKit 입력을 유지한다. 점선은 iPadOS 26에서
  제공되는 공개 PencilKit 획 모델을 사용해 Pencil-only 경로로 만들고
  `PaperMarkup`에 추가한다.
- 45도 형광펜은 현재 native 입력을 유지하고, 0도와 90도만 고정 각도
  획 생성 경로를 시험한다.
- 색상은 흰 PDF의 고정 light appearance에서 저장·표시하며, 부분/정밀
  지우개는 조절 가능한 고정 폭을 사용하고 전체/획 지우개는 선택 폭의
  hover 범위를 표시한다.
- 이미지 도구 아래에는 PhotoKit의 최신순 미리보기와 파일 불러오기를
  제공한다. 직접 최근 항목을 읽으려면 소비 앱에 Photo Library capability가
  필요하며, 없을 때는 시스템 PhotosPicker를 안전한 대체 경로로 둔다.

### 3단계 — `0.1.27`: PDF 페이지 기하만 수정

툴바가 통과한 뒤 PDF 관련 변경을 별도 버전에서 수행한다.

- CropBox, MediaBox, 0이 아닌 box 원점과 `/Rotate`를 하나의 페이지
  기하 값으로 정규화한다.
- 기본 전체 페이지 이미지, 고해상도 타일, PaperKit bounds, 초기 fit과
  미래 내보내기가 같은 변환을 사용한다.
- **자동 / 잘린 영역 / 전체 미디어 영역** 표시 정책을 검토한다.
- 기존 `0.1.19` 타일 크기, LOD, 캐시 수, 요청 순서와 핀치 정책은
  바꾸지 않는다.
- 기존 필기 파일을 덮어쓰지 않고 기하 서명과 복구 사본을 사용한다.

iPadOS 26 합격 시험:

1. 사용자가 이미 알려준 실패 스캔 PDF가 잘리지 않아야 한다.
2. 기존 정상 PDF의 방향·비율은 바뀌지 않아야 한다.
3. 세로, 가로, 회전, 서로 다른 페이지 크기에서 fit과 확대 범위가
   일관돼야 한다.
4. 확대 후 필기, 페이지 이동, 재실행 뒤에도 글씨가 같은 인쇄 위치에
   있어야 한다.
5. 렌더링 속도와 이동 중 선명도가 `0.1.19`보다 나빠지지 않아야 한다.

## 단계 공통 규칙

1. 새 기능보다 기존 필기 데이터 보존을 우선한다.
2. 기존 정상 PDF와 알려진 실패 PDF를 모두 시험한다.
3. Windows 정적 검사, Apple CI 빌드, Simulator 시험, Swift Playgrounds
   컴파일, 실제 iPad 동작을 각각 별도 증거로 기록한다.
4. CI 통과를 실제 Apple Pencil 시험 통과로 간주하지 않는다.
5. iPad 시험이 끝나기 전에는 다음 버전 태그를 만들지 않는다.
6. 한 단계가 실패하면 원인을 확인하거나 사용자가 명시적으로
   트레이드오프를 수용할 때까지 다음 단계로 넘어가지 않는다.
7. 대용량 PDF 메모리 구조는 실제 메모리 경고·크래시·측정 결과가
   생기기 전까지 변경하지 않는다.
8. 공개 Apple API와 유지되는 공개 소스를 먼저 검토하고, 외부 패키지
   의존성은 사용자 승인 없이 추가하지 않는다.
